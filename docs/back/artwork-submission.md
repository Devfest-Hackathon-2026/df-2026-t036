# 作品投稿API（サーバー実装）

## リクエスト

`POST /api/v1/artworks` にFirebase IDトークンとmultipartの`ideaId`、`file`を送る。初回確定は201、同じ画像バイト列の再送は200で同じ`submissionId` / `submittedAt`を返す。入力上限20 MiB、本文上限20 MiB + 64 KiB。Flutterの通常送信ボタンへの接続は別作業。

## 資格と審査

- 登録済みactiveの描き手と受信者。自分のお題、削除・欠損・受付期限到達は不可。
- 7日未満はピン不要。7〜30日未満は現在保持中の事前ピンが必要。
- 描き手×お題のSHA-256をsubmissionIdとする。履歴は画像削除後も維持し、1人1お題1回を保証する。
- 入力の実形式・容量・画素数・静止画・デコードをサーバーで検証し、正規化する。
- Visionへ直接送信し、全5カテゴリがPOSSIBLE以下の場合だけ承認。LIKELY以上は422 IMAGE_REJECTED、不明・障害は503で未確定。
- 審査成功後にWebPへ変換し、正式保存する。Vision用の一時Storage保存は行わない。

## StorageとFirestore

`ARTWORK_BUCKET`に非公開バケット名を設定する。APIのADC実行主体に、そのバケットのオブジェクト作成・削除・読取権限と、Vision / Firestoreの必要権限を設定する。バケットは公開しない。画像パスや公開URLは投稿応答へ含めない。

作品・描いた履歴・drawnCount・処理完了状態を一つのFirestoreトランザクションで確定する。資格は予約時と確定時に検証し、途中の停止・削除・ピン解除・期限到達も反映する。保存した作品の期限は確定時刻＋7日。

`artworkSubmissions/{submissionId}`は予約状態・入力SHA-256・試行token・有効期限・完了結果を記録する。未完了の予約は30分有効で、処理中の並行送信は409。異なる画像で確定済み投稿を再送しても409で置換しない。確定済みの再送は資格期限が過ぎても本人へ同じ結果を返す。

`artworkUploads/{token}`は試行ごとのbucket・storagePath・状態・期限を記録する。画像パスは試行ごとに変え、`if_generation_match=0`で既存画像の上書きを防ぐ。作成前に記録を残し、途中でサーバーが停止しても回収対象が追跡できる。

## 失敗と回収

DBの確定結果が不明な場合は、先にFirestoreトランザクションで状態を確認する。確定済みなら画像を削除しない。未確定なら試行をabandonedへ変更し、以後その試行の確定を禁止したうえで画像を削除する。削除失敗時は追跡文書を残す。

`POST /api/v1/internal/artwork-cleanup`は既存cleanupと同じ専用サービスアカウントOIDCで認可し、期限到達・回収失敗の記録を最大100件処理する。メンテナンス中も利用可能。body・queryは不要。`scanned` / `scannedObjects` / `failed` / `hasMore`を返す。hasMoreがtrueなら再実行する。Cloud Scheduler等で定期実行を設定する必要がある。

この回収APIは未確定画像を対象とする。7日経過した確定作品の物理削除、画像取得・ダウンロードAPI、Flutterの通常送信は今回の対象外。既存の受信箱・描いた履歴・累計APIは確定した投稿をそのまま取得できる。

## 実環境確認

単体・HTTPテストは外部サービスをfakeに置き換える。開発用GCPでARTWORK_BUCKET・ADC・Vision・Firestore・内部OIDCとSchedulerを設定し、成功、拒否、再送、回収を確認する。本実装はバケット作成やIAM変更・デプロイを自動では行わない。

### 停止プロセスが遅れて画像を保存した場合

回収APIは保存先のartworks/も1回最大100オブジェクト、ページ位置を保持して巡回する。試行記録がなく、確定作品からも参照されない画像だけをgeneration一致条件付きで削除する。処理の停止・再開が記録削除と前後しても孤立画像を回収できる。確定作品の画像はこの走査では削除しない。
