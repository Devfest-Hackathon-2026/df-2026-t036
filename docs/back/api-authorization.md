# APIの認可

## 基本方針

Firebase IDトークンの署名・有効期限・失効とGoogleログインを検証し、UIDはトークンから取得する。本文やクエリで指定されたUIDを操作主体として採用しない。

| API | 必要な権限 |
|---|---|
| `/health` | 認証不要 |
| `/api/v1/users/register` | Google認証済み。既存の停止ユーザーは登録処理でも拒否 |
| お題・ピン・履歴・作品操作・Visionデモ | Google認証済み、Firestore登録済み、statusがactive |
| `/api/v1/internal/cleanup` | 専用サービスアカウントのOIDCトークンと設定したaudience |

通常APIのルーター登録時に`Depends(active_user)`を設定する。これにより新しいエンドポイントにも同じ認可を適用する。新規ルーターを追加する場合も、公開範囲に応じてこの依存関係を指定する。

## リソース単位の権限

お題削除は所有者のみ、作品の既読・いいねは受信者のみ許可する。本人の一覧・履歴・ピンは認証したUIDで検索する。他人の非公開リソースや存在しないリソースは404として扱い、存在情報を漏らさない。

更新トランザクション内のユーザー状態・権限の再確認は維持する。入口の認可後に停止・データ変更が起きた場合にも対応するためである。

未認証は401、停止ユーザーは403、未登録ユーザーは404を返す。初回登録は通常APIのactive制限から分離する。

## 検証

`back/tests/test_api_authorization.py`で、全利用者APIの未認証拒否、通常APIの未登録・停止ユーザー拒否、他人のお題削除・作品操作で書込みが発生しないことを検証する。実クラウドの認証接続とは分け、外部接続なしで実行する。
