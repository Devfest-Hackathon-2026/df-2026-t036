# プロフィールの編集・受信者への公開

プロフィール編集と受信作品からの作者閲覧の現行仕様をまとめています。旧M2計画2文書を統合しました。画面全体は [デザインガイド](../flont/design.md)、保存項目は [DB・API仕様](../database/DB_v0.md) を参照してください。

## 本人の編集

- マイページの「プロフィールを編集」でユーザーネーム・自己紹介・SNSリンクを更新します。
- `GET /api/v1/me` で取得し、`PATCH /api/v1/me/profile` で本人の情報を更新します。
- ユーザーネームは1〜24文字。未指定なら既存値を保持します。空白だけ・制御文字は拒否します。
- 自己紹介 `bio` は最大300文字、SNS `socialLinks` は最大5件。更新時には両項目を送ります。
- リンクは `type`・`label`（1〜40文字）・`url`（1〜2048文字）。種別は `x`・`instagram`・`pixiv`・`youtube`・`other`。
- HTTPSだけを受け付け、資格情報付きURLと重複URLを拒否します。既知SNSの種別ではホストも検証します。
- 新旧ユーザーとも未保存の `bio`・`socialLinks` は空文字・空リストとして取得できます。一括DB移行は行わず、編集保存時に書き込みます。
- 登録の再送で名前・累計・枠・ピンを初期化しません。登録応答と保存済みプロフィールの取得は区別し、最新プロフィールは `GET /api/v1/me` で取得します。

## 作品ごとの公開選択

`POST /api/v1/artworks` のmultipart項目 `shareArtistProfile` は既定falseです。公開を選んだ作品に `artistProfileVisibleToRecipient` を保存します。チェックを外した送信では、作者情報を受信者に公開しません。

受信箱・作品詳細では `artistProfileAvailable` を使って作者名・導線を切り替えます。公開時は `GET /api/v1/me/artworks/{submission_id}/artist-profile` で現在の作者情報を取得します。返すのは `uid`・`nickname`・`bio`・`socialLinks` です。メールや非公開カウンターは返しません。

次の条件をすべて満たす場合だけ取得できます。

- 認証・登録済みactiveの受信者本人である。
- 作品が存在し、未削除かつ閲覧期限内である。
- 送信時に作者がプロフィール公開を選んでいる。
- 作者ユーザーが存在し、activeである。

不許可・欠損・期限切れは共通404です。一般公開のプロフィールURLや、相手のお題カード一覧は提供しません。作者プロフィールを編集すると、公開済み作品からも最新内容が表示されます。

## 画面確認

[起動方法](../startup.md) のプレビューでは編集結果は起動中の画面内だけに反映します。永続保存・権限・非公開・期限切れの確認は通常ログインで行います。

外部リンクでは遷移先を確認できる表示にし、ブラウザーで開けない場合の失敗表示も確認します。スマホ・タブレット・PC幅で編集・閲覧を確認してください。

## 今後の検討

アイコン・代表作品、プロフィール全体の一般公開、公開累計、報告・ブロックは今回の対象外です。導入時には画像の権利・審査・容量・保持期限・削除、一般公開範囲、リンク悪用時の運用を別途決めます。受信者限定画像を代表作品として流用しません。

# M2計画：SNSリンクとプロフィール拡張

- 作成日: 2026年11月9日
- 状態: 送信ごとのプロフィール公開・受信者閲覧は実装済み。画像拡張等は計画案
- 対象: Flutter Web / FastAPI / Firestore / Cloud Storage

## 1. 目的

描き手が自分の活動場所や作品をプロフィールから案内でき、お題主・描き手が創作者の作風や活動を知ったうえで交流できる状態をつくる。M1の「匿名性を保ったランダムニックネーム」「外部SNS連携はM2以降」という方針を引き継ぎ、Googleの本名・メールアドレスは公開プロフィールに流用しない。

## 2. 現状と前提

### 実装済み

- GoogleログインとFirebase IDトークン検証、初回登録と再試行に対応。
- Firestore `users/{uid}` にランダムな `nickname`、`status`、`ideaCount`、`drawnCount`、`likesReceived` を保存。
- `POST /api/v1/users/register` と `GET /api/v1/me` は本人の公開を意図しない集計・基本情報を返す。`Me` DTOで返却項目を明示している。
- Flutterに `ProfileScreen` と表裏切替式の `ProfileCard` があり、ニックネーム・3つの累計、アイデア履歴・描いた履歴、設定への導線を表示。
- 自分の自己紹介・SNSリンクの編集画面があり、認証付き `PATCH /api/v1/me/profile` でサーバー保存する。保存後の応答をプロフィール表示へ反映する。
- 同じ編集画面からユーザーネーム（`nickname`）も保存できる。1〜24文字、前後空白を除去し、空欄・制御文字は拒否する。初回登録時のランダム生成は未設定時の初期値として継続する。
- 自己紹介は最大300文字、SNSリンクは最大5件。HTTPS・既知SNSドメイン・重複URLをフロント/バック両側で確認する。
- 作者ニックネームはTL/受信箱の既存応答に含まれる。
- 受信作品の送信時にプロフィール公開を選び、受信者だけが作者プロフィールを取得できるようにした。非公開の場合は受信箱応答から作者IDと名前を省き、広域プロフィールAPIを削除した。
- Firestoreクライアント直接アクセスはルールで拒否し、FastAPIがデータアクセスを担当。

### 未実装または未決定

- アイコン画像、代表作品の登録・編集・削除・公開方法。
- 他ユーザーのプロフィールをタイムライン等、作品受信者以外にも公開する全体公開機能。
- SNS連携をOAuth認証とするか、単なる外部リンク登録とするか。
- 既存の受信作品は受信者限定・7日保持であるため、公開プロフィールの代表作品として自動利用できない。

## 3. 推奨するM2初回リリースの範囲

### プロフィール

- 閲覧ページ: ニックネーム、任意の自己紹介、任意のアイコン、任意の代表作品、登録したSNSリンクを表示。
- 編集ページ: 本人だけがユーザーネーム、自己紹介、SNSリンクを更新できる。ユーザーネームは1〜24文字で重複を許可し、識別子はUIDとする。
- アイコン: 任意設定。未設定時は既定アバターを表示。画像アップロードを行う場合は許可形式・サイズ・寸法・変換方式・旧画像削除の順序を実装前に固定。
- 代表作品: 初回は公開同意を得たプロフィール専用アップロードを推奨。既存の受信作品は選択肢にしない。所有者が公開権利を確認して設定し、いつでも差替え・削除可能にする。
- 公開プロフィールに集計値を出すかは別途決定。公開する場合も個人の活動量に関する値だけを対象にし、人気順・ランキングには使わない。
- イラスト送信時に「この作品の受信者にプロフィールを公開する」を選べるようにする。初期値はオフとし、非公開ではユーザーネーム・自己紹介・SNSリンクを相手に表示しない。詳しい契約は[受信作品から描き手プロフィールを表示する計画](profile.md)を参照。

### SNSリンク

- 初回はOAuthによるアカウント接続ではなく、ユーザーが登録する外部URLリンクとして実装する。SNSログイン・投稿・フォロー状態の取得は含めない。
- 対応先は需要に基づき、例としてX、Instagram、pixiv、YouTube、その他のHTTPS URLを候補にする。正式な候補は仕様決定時に確定する。
- URLはHTTPSのみ許可し、許可するホスト名と正規化規則をサーバーで検証する。任意URLを許す場合は警告画面を挟み、`javascript:` 等のスキームを拒否する。
- 1プロフィールあたりの登録数上限を設ける（案: 5件）。SNS種別・URL・表示名・順序を保存し、同一URLの重複を拒否。
- 外部リンクを開く際、利用者に外部サイトへ移動することを明示する。リンク先を埋め込み表示しない。

## 4. データ/API案

既存の `users/{uid}` は内部カウンター・アカウント状態とプロフィール内容を保持する。プロフィール情報を読む場合は作品ごとの公開許可と受信関係を必ず確認する。受信者限定APIは作品文書から作者UIDを取得し、クライアント指定のUIDを認可に使わない。将来、作品受信者以外にもプロフィールを公開する要件が出た場合に限り、全体公開設定と専用文書を別途設計する。

公開文書の候補フィールド:

```text
nickname: string                  # users/{uid} と一貫させる
bio: string                       # 任意、上限は仕様決定（案: 300文字）
avatarPath: string | null         # Storage内の固定ユーザーパス
featuredWorkPath: string | null   # 公開同意済みのプロフィール専用画像
socialLinks: [{type, label, url, sortOrder}]
visibility: "public" | "unlisted" | "private"
updatedAt: timestamp
```

上記のプロフィール文書は将来の全体公開を含む拡張候補であり、送信ごとの公開許可だけを導入する初回実装では追加しない。送信単位の公開選択は作品文書に置く。

カウンターは公開プロフィール文書へ重複保存せず、公開を決定した場合にだけ本人・公開APIの応答へ安全に合成する。Storageは公開用プロフィール画像と既存の非公開作品画像でバケットまたはパス・認可を分ける。ランダムで推測困難なUIDを公開URLとして露出する設計に依存しない。

API候補（送信ごとの公開選択を実装する時点で、既存の広域公開APIを置き換える）:

| API | 用途 | 認可 |
|---|---|---|
| `GET /api/v1/me/artworks/{submissionId}/artist-profile` | 受信作品の描き手プロフィール取得 | 認証済み受信者。作品の公開選択・受信者・期限・削除状態をサーバー検証 |
| `PATCH /api/v1/me/profile` | ユーザーネーム・自己紹介・リンク更新 | 本人のみ、許可フィールドの明示 |
| `POST /api/v1/me/profile/avatar` | アイコン登録・差替え | 本人のみ、画像検証後 |
| `DELETE /api/v1/me/profile/avatar` | アイコン削除 | 本人のみ |
| `POST /api/v1/me/profile/featured-work` | 代表作品登録・差替え | 本人のみ、公開同意と画像検証 |
| `DELETE /api/v1/me/profile/featured-work` | 代表作品削除 | 本人のみ |

画像APIは既存の画像アップロード設計を再利用しつつ、作品投稿のSafeSearch・WebP変換・サイズ上限・失敗時の掃除を適用する。署名付きURLを利用する場合も短い有効期限とパス所有者確認を行い、公開プロフィール画像の公開仕様と混同しない。

## 5. 画面・導線

1. マイページのプロフィールカードから「プロフィールを編集」を開く。
2. 自己紹介、アイコン、代表作品、SNSリンクを編集し、保存前プレビューを確認する。
3. 保存成功後に公開プロフィール表示へ反映し、失敗時は入力内容を保持して再試行できる。
4. イラスト送信時にプロフィール公開を選んだ作品だけ、受信者が作品詳細から作者プロフィールへ移動する。
5. 公開プロフィールには「外部サイトへ移動」操作を置き、リンク先を開く前にドメインを示す。
6. 送信時に非公開を選んだ作品では作者名とプロフィール導線を隠す。期限切れ・削除済みプロフィール、通信失敗を区別し、画面単位で再試行可能にする。

既存の表裏カードは累計の表示に使い続けるか、プロフィール情報を見せるカードへ変えるか、編集導線をどこへ置くかを画面仕様で決める。

## 6. 実装順

1. **仕様決定**: SNS候補、リンク数、公開範囲、自己紹介上限、プロフィールIDの扱い、集計値公開、代表作品の登録元、画像制限、退会・停止時の扱いを決定。
2. **データ/API**: 作品に送信単位のプロフィール公開選択を保存し、受信箱応答で非公開の作者ID・名前を省く。受信関係を検証するプロフィール取得APIを実装し、広域取得可能な既存APIは廃止または本人専用に制限する。
3. **SNSリンク**: HTTPS/ホスト検証、重複・件数・順序制御、編集UI、外部遷移確認を実装。
4. **プロフィール画像**: Storageパス、アップロード検証、差替え、旧画像掃除、表示APIを実装。
5. **代表作品**: 公開同意を明示する登録UI、専用画像保存、削除・差替えを実装。
6. **他者プロフィール閲覧**: 描き手が送信時に公開を選んだ作品の受信者だけに導線を表示し、参照不可・通信エラーを処理。
7. **運用・移行**: 既存ユーザーに空のプロフィールを遅延作成するか、初回編集時に作るか決め、ログ・削除・Storage掃除を整える。

## 7. 受け入れ条件

- 公開APIは許可したプロフィール項目だけを返し、Googleメール・内部UID属性・認証情報・非公開カウンターを返さない。
- 本人以外の更新、未知フィールド、過大入力、不許可URLスキーム、URL件数超過、重複リンクを拒否する。
- 送信画面の既定値は非公開で、プロフィール情報が未設定でも作品を送信できる。
- 非公開選択では受信者にユーザーネーム・自己紹介・SNSリンクが漏れず、作品の受信・閲覧・いいね・保存は通常どおり動作する。
- 既存のプロフィール取得APIを使って送信単位の非公開を迂回できない。
- SNSリンクはWeb/スマホ幅で内容を確認でき、外部遷移先を明示して開ける。
- 代表作品に既存の受信者限定作品画像を流用できず、プロフィール所有者が公開同意した画像だけを表示する。
- アイコン・代表作品の差替えや削除で古い画像が残留せず、削除失敗は追跡・再試行できる。
- Firestore直接アクセス拒否を維持し、APIの認可とStorageパス所有者確認を行う。
- 既存ユーザー、プロフィール未作成、停止、非公開、画像期限切れ、通信失敗の表示を確認する。
- iPad・スマホ・PCの主要幅で編集・閲覧・外部遷移を確認する。

## 10. バックエンド実装状況・フロント設計引き継ぎ

自己紹介・SNSリンク・ユーザーネームの本人編集API/画面、作品送信ごとのプロフィール公開選択、受信者限定プロフィールAPI、作者プロフィール画面は実装済み。アイコン・代表作品の画像APIは未実装。現在のAPI契約は次の通り。

### API契約

| Method / path | 認証 | 画面での使い方 |
|---|---|---|
| `GET /api/v1/me` | Firebase ID token、activeユーザー | マイページ表示と編集後の最新値取得 |
| `PATCH /api/v1/me/profile` | Firebase ID token、activeユーザー | 編集フォーム保存。nickname（省略可）、自己紹介とSNSリンクを一括置換 |
| `GET /api/v1/users/{uid}/profile` | — | 広域取得を防ぐため削除済み |
| `GET /api/v1/me/artworks/{submissionId}/artist-profile` | Firebase ID token、作品の受信者 | 送信時に公開を選んだ作品に限り作者プロフィールを表示 |

更新リクエスト例（実データではなく形式例）:

```json
{
  "nickname": "そらのアトリエ",
  "bio": "水彩で風景を描いています。",
  "socialLinks": [
    {"type": "pixiv", "label": "pixiv", "url": "https://www.pixiv.net/users/example"},
    {"type": "x", "label": "X", "url": "https://x.com/example"}
  ]
}
```

成功時は本人情報一式（`uid`, `nickname`, `status`, `ideaCount`, `drawnCount`, `likesReceived`, `bio`, `socialLinks`）を返す。受信者限定プロフィール取得は `uid`, `nickname`, `bio`, `socialLinks` のみ返す。未登録プロフィール項目は `bio: ""` と `socialLinks: []` で返す。公開選択値がない作品は非公開として扱う。

入力制約:

- `bio`: 300文字まで。空欄可。
- `nickname`: 1〜24文字。前後空白を除去し、空欄・制御文字を拒否。省略時は既存値を維持。重複は許可し、UIDで識別する。
- `socialLinks`: 0〜5件。各要素は `type`, `label`, `url`。
- `type`: `x`, `instagram`, `pixiv`, `youtube`, `other` のいずれか。
- `label`: 1〜40文字。
- `url`: 1〜2048文字、HTTPS必須。既知SNS種別は対応ドメインを検証。`other` は任意のHTTPSドメイン。
- URL重複は末尾スラッシュと大文字小文字を正規化して拒否。
- 更新は一括置換。リンクの追加・削除・並び替えは、編集画面でフォーム配列を組み立てて一度に保存する。
- 実績数の編集UIは作らない。プロフィール写真・代表作品の入力欄も、対応APIが追加されるまでは表示しない。

エラー応答は共通形式 `{"error":{"code":"...","message":"...","details":null,"requestId":"..."}}`。入力エラーは422、未ログインは401、停止ユーザーは403、存在しない/参照不可プロフィールは404、サービス障害は503。編集画面では422をフォーム入力の再確認として扱い、通信障害時は入力内容を保持して再試行できる設計にする。

### 画面設計への推奨

1. **自分のプロフィール閲覧**: 現行プロフィールカードと履歴導線を維持し、自己紹介・SNSリンク欄と「プロフィールを編集」導線を加える。実績数は本人画面だけに表示。
2. **プロフィール編集**: 自己紹介の文字数カウンター（`現在/300`）、SNSリンクを最大5行まで管理できる追加・削除・並べ替え操作、URL入力、保存中・保存成功・入力エラーを設ける。未保存変更がある状態で戻る場合は破棄確認を出す。
3. **他者プロフィール**: 描き手が送信時に公開を選んだ作品の受信者だけに、最新のユーザーネーム、自己紹介、SNSリンクを表示。非公開作品ではユーザーネームを含めてプロフィール情報と導線を表示しない。本人用編集ボタン・実績数・メールアドレスは表示しない。
4. **外部リンク**: 表示ラベルとドメインを確認できる行/ボタンにする。タップ時は外部サイトへ移動することを明示し、URLをアプリ内WebViewへ埋め込まない。
5. **状態**: 初回ローディング、プロフィール未入力、リンクなし、参照不可、通信失敗（再試行）、保存中、保存失敗をデザインする。APIの404は「プロフィールを表示できません」、通信エラーは再試行可能な別状態として扱う。
6. **レスポンシブ**: 既存の `PageLayout` と共通テーマを使い、スマホ・タブレット・PCで同じ情報階層を保つ。長いリンクや自己紹介は折り返し、横はみ出しを避ける。

# M2実装案：受信作品から描き手プロフィールを表示

- 作成日: 2026年11月9日
- 状態: 次段階の実装案
- 関連: [SNSリンク・プロフィール拡張計画](profile.md)

## 1. 目的と利用場面

お題主が受信作品を確認するとき、描き手のプロフィールを開き、自己紹介と登録済みのSNSリンクを見られるようにする。受信作品画像や非公開の受信箱情報を描き手へ見せる仕組みは追加しない。

## 2. 現在利用できるデータ/API

- `GET /api/v1/me/artworks/inbox` の `InboxItem` は公開選択がある作品に限り `artistId` と `artistNickname` を返す。非公開作品では双方をnullにし、`artistProfileAvailable` をfalseにする。
- Flutterの `ReceivedArtwork` は `artistId` / `artistNickname` をnullableとして扱い、プロフィール公開可否も保持する。
- `GET /api/v1/me/artworks/{submissionId}/artist-profile` は許可された受信作品から `uid`, `nickname`, `bio`, `socialLinks` のみを返す。メール・実績数・内部データは含めない。
- `nickname` は本人が `PATCH /api/v1/me/profile` で変更できる。受信箱には取得時点の名前を表示し、プロフィール画面ではAPIから取得した最新名を表示する。
- 旧 `GET /api/v1/users/{uid}/profile` は削除し、送信ごとの公開選択を迂回できる経路を閉じた。

## 3. 描き手が送信ごとに公開を選ぶ方針

- イラスト送信画面に「この作品の受信者にプロフィールを公開する」選択欄を置く。公開する場合、受信者はユーザーネーム・自己紹介・SNSリンクを確認できる。
- 初期値はオフとする。プロフィール公開を望む描き手が明示的にオンにして送信する。プロフィール自体を未入力でも作品送信はできる。
- 選択値は作品確定時に `artworks/{submissionId}.artistProfileVisibleToRecipient` として保存し、送信完了後は変更不可とする。途中失敗後の再試行でも、確定済みの値を変更しない。
- オフの場合、受信箱APIは `artistId` と `artistNickname` を返さず、作者名は「非公開」とする。プロフィール導線も出さない。作品の送信・閲覧・いいね・保存権限には影響させない。
- オンの場合、受信箱APIはプロフィール導線に必要な作品IDと作者情報を返す。作品詳細から開くプロフィールは、送信時のスナップショット名ではなく、作者IDで取得した最新名を表示する。
- 既存作品で公開選択値がない場合は非公開として扱い、一覧応答やプロフィールAPIの判定で fail-closed とする。必要ならリリース前に移行・案内方針を決める。

## 4. 推奨する画面導線

1. 描き手の送信確認画面に公開選択欄を置き、共有する項目（ユーザーネーム・自己紹介・SNSリンク）と受信者を明示する。
2. 公開設定がある受信作品詳細のみ、作者情報行を「プロフィールを見る」操作にする。非公開作品は「作者プロフィールは非公開」と表示する。
3. タップ時に `submissionId` で受信者限定プロフィールAPIを呼び、`PublicProfileScreen` を開く。受信一覧へ戻ったときに作品一覧や既読状態を再初期化しない。
4. プロフィール画面には最新のユーザーネーム、自己紹介、SNSリンクだけを表示する。作品画像、アイコン、実績数、Googleメール、編集ボタンは出さない。
5. 未入力の自己紹介・SNSリンクは空欄表示を避け、「プロフィール情報はまだありません」という空状態にまとめる。

## 5. Flutter変更候補

| ファイル | 変更 |

| `flont/lib/screens/artwork_detail_screen.dart` | 作者情報行をプロフィール遷移操作にする |
| `flont/lib/screens/inbox_screen.dart` | 認証済みAPI・ID token providerを詳細画面へ渡す |

公開プロフィール表示には `PageLayout` と `AppTheme` を使い、スマホ・タブレット・PCで同じ情報順を維持する。外部リンクを開く場合はホスト名を見せ、「外部サイトを開く」と明示して別タブへ移動する。画面内WebViewは使わない。

## 6. APIの公開範囲・認可

- `GET /api/v1/users/{uid}/profile` は削除済み。受信者向けの `GET /api/v1/me/artworks/{submissionId}/artist-profile` は作品の `recipientId`・`artistProfileVisibleToRecipient`・期限・削除状態をサーバー側で検証してから、許可項目だけを返す。
- リクエストから作者UID・受信者UIDを受け取らず、作品文書から作者UIDを決める。非公開・不存在・期限切れ・削除済み・受信者でない場合は同一の404 `RESOURCE_UNAVAILABLE` とし、プロフィールの存在や関係を漏らさない。
- 受信箱一覧もサーバーで公開フラグを確認し、非公開の場合は `artistId` と `artistNickname` を応答から省く。クライアントでリンクを隠すだけの実装にしない。

## 7. 実装内容

1. 送信画面の公開選択（既定オフ）をmultipart APIへ送り、作品確定時に公開フラグを保存する。
2. 公開フラグがない過去作品は非公開として扱い、受信箱APIから作者ID・名前を隠す。
3. 受信者専用の作品プロフィールAPIを追加し、旧広域プロフィール取得APIを削除する。
4. 作品詳細からプロフィール画面を開き、認証付きで最新プロフィールを取得する。
5. SNSリンクを外部ブラウザーで開く前にホスト名を確認する。

実装コードは追加済み。実Firebaseを使った認証・保存やブラウザーでの一連の操作は、ここでは未確認。

## 8. 受け入れ条件

- 受信作品詳細から作者プロフィールを開き、戻ると同じ作品詳細・受信箱状態へ戻れる。
- API応答の `uid`, `nickname`, `bio`, `socialLinks` のみ表示し、累計やメールを表示しない。
- プロフィールが空でも受信作品の閲覧・いいね・保存は妨げない。
- 参照不可と通信失敗を異なる表示にし、通信失敗は再試行できる。
- 作品画像のURL・Storageパス・相手の受信箱情報をプロフィール画面へ渡さない。
- 描き手が非公開を選んだ場合、受信箱のAPI応答・UI・プロフィールAPIの全経路でユーザーネーム、自己紹介、SNSリンクを見られない。
- 非公開設定は受信者本人に紐づく作品IDだけで検証し、作者UIDやrecipient UIDのクライアント指定で迂回できない。
- 送信再試行・二重送信でも確定した公開選択が変わらず、公開設定がない過去作品は非公開として扱う。
- SNSリンクはURLのホストを表示して外部遷移することを分かる形にする。
- 過去の作品詳細に保持された送信時点の作者名と、プロフィールAPIが返す最新のユーザーネームを画面上で混同させない。
- スマホ320px・タブレット768px・PC1280pxで横はみ出しがない。
- 作品期限到達・手動削除後に作品詳細の操作を続行できない現行ルールを維持する。

## 9. 開発時に必要な確認

- 公開チェック欄の文言と既定値（本案はオフ）をデザイン確定時に確認する。
- 作品閲覧期限後にプロフィールへの導線を残さないことを確認する。
- `other` SNSリンクの警告文と、外部ブラウザー起動の可否を確認する。
- 将来、送信ごとの選択とは別にプロフィール全体の公開・非公開設定を導入する場合は、タイムライン等の名前表示・プロフィール遷移も合わせて設計する。
