# M2実装案：受信作品から描き手プロフィールを表示

- 作成日: 2026年11月9日
- 状態: 次段階の実装案
- 関連: [SNSリンク・プロフィール拡張計画](m2-social-profile-plan.md)

## 1. 目的と利用場面

お題主が受信作品を確認するとき、描き手のプロフィールを開き、自己紹介と登録済みのSNSリンクを見られるようにする。受信作品画像や非公開の受信箱情報を描き手へ見せる仕組みは追加しない。

## 2. 現在利用できるデータ/API

- `GET /api/v1/me/artworks/inbox` の `InboxItem` は公開選択がある作品に限り `artistId` と `artistNickname` を返す。非公開作品では双方をnullにし、`artistProfileAvailable` をfalseにする。
- Flutterの `ReceivedArtwork` は `artistId` / `artistNickname` をnullableとして扱い、プロフィール公開可否も保持する。
- `GET /api/v1/me/artworks/{submissionId}/artist-profile` は許可された受信作品から `uid`, `nickname`, `bio`, `socialLinks` のみを返す。メール・実績数・内部データは含めない。
- `nickname` は本人が `PATCH /api/v1/me/profile` で変更できる。受信箱には取得時点の名前を表示し、プロフィール画面ではAPIから取得した最新名を表示する。
- 旧 `GET /api/v1/users/{uid}/profile` は削除し、送信ごとの公開選択を迂回できる経路を閉じた。

## 3. 描き手が送信ごとに公開を選ぶ方針

- イラスト送信画面に「この作品の受信者にプロフィールを公開する」選択欄を置く。公開する場合、受信者はユーザーネーム・自己紹介・SNSリンクを確認できる。
- 初期値はオフとする。プロフィール公開を望む描き手が明示的にオンにして送信する。プロフィール自体を未入力でも作品送信はできる。
- 選択値は作品確定時に `artworks/{submissionId}.artistProfileVisibleToRecipient` として保存し、送信完了後は変更不可とする。途中失敗後の再試行でも、確定済みの値を変更しない。
- オフの場合、受信箱APIは `artistId` と `artistNickname` を返さず、作者名は「非公開」とする。プロフィール導線も出さない。作品の送信・閲覧・いいね・保存権限には影響させない。
- オンの場合、受信箱APIはプロフィール導線に必要な作品IDと作者情報を返す。作品詳細から開くプロフィールは、送信時のスナップショット名ではなく、作者IDで取得した最新名を表示する。
- 既存作品で公開選択値がない場合は非公開として扱い、一覧応答やプロフィールAPIの判定で fail-closed とする。必要ならリリース前に移行・案内方針を決める。

## 4. 推奨する画面導線

1. 描き手の送信確認画面に公開選択欄を置き、共有する項目（ユーザーネーム・自己紹介・SNSリンク）と受信者を明示する。
2. 公開設定がある受信作品詳細のみ、作者情報行を「プロフィールを見る」操作にする。非公開作品は「作者プロフィールは非公開」と表示する。
3. タップ時に `submissionId` で受信者限定プロフィールAPIを呼び、`PublicProfileScreen` を開く。受信一覧へ戻ったときに作品一覧や既読状態を再初期化しない。
4. プロフィール画面には最新のユーザーネーム、自己紹介、SNSリンクだけを表示する。作品画像、アイコン、実績数、Googleメール、編集ボタンは出さない。
5. 未入力の自己紹介・SNSリンクは空欄表示を避け、「プロフィール情報はまだありません」という空状態にまとめる。

## 5. Flutter変更候補

| ファイル | 変更 |
|---|---|
| `flont/lib/screens/artwork_detail_screen.dart` | 作者情報行をプロフィール遷移操作にする |
| `flont/lib/screens/inbox_screen.dart` | 認証済みAPI・ID token providerを詳細画面へ渡す |
| 送信確認画面 | 受信者へのプロフィール公開チェックを追加し、送信APIへ選択値を渡す |
| `flont/lib/models/received_artwork.dart` | `artistId` / `artistNickname` をnullableとし、公開可否フラグを保持 |
| `flont/lib/screens/public_profile_screen.dart` | 受信作品IDからプロフィール取得、表示、ローディング・再試行・参照不可を実装 |
| `flont/lib/services/authenticated_api.dart` | 既存GETクライアントを再利用。PATCH追加は不要 |

公開プロフィール表示には `PageLayout` と `AppTheme` を使い、スマホ・タブレット・PCで同じ情報順を維持する。外部リンクを開く場合はホスト名を見せ、「外部サイトを開く」と明示して別タブへ移動する。画面内WebViewは使わない。

## 6. APIの公開範囲・認可

- `GET /api/v1/users/{uid}/profile` は削除済み。受信者向けの `GET /api/v1/me/artworks/{submissionId}/artist-profile` は作品の `recipientId`・`artistProfileVisibleToRecipient`・期限・削除状態をサーバー側で検証してから、許可項目だけを返す。
- リクエストから作者UID・受信者UIDを受け取らず、作品文書から作者UIDを決める。非公開・不存在・期限切れ・削除済み・受信者でない場合は同一の404 `RESOURCE_UNAVAILABLE` とし、プロフィールの存在や関係を漏らさない。
- 受信箱一覧もサーバーで公開フラグを確認し、非公開の場合は `artistId` と `artistNickname` を応答から省く。クライアントでリンクを隠すだけの実装にしない。

## 7. 実装内容

1. 送信画面の公開選択（既定オフ）をmultipart APIへ送り、作品確定時に公開フラグを保存する。
2. 公開フラグがない過去作品は非公開として扱い、受信箱APIから作者ID・名前を隠す。
3. 受信者専用の作品プロフィールAPIを追加し、旧広域プロフィール取得APIを削除する。
4. 作品詳細からプロフィール画面を開き、認証付きで最新プロフィールを取得する。
5. SNSリンクを外部ブラウザーで開く前にホスト名を確認する。

実装コードは追加済み。実Firebaseを使った認証・保存やブラウザーでの一連の操作は、ここでは未確認。

## 8. 受け入れ条件

- 受信作品詳細から作者プロフィールを開き、戻ると同じ作品詳細・受信箱状態へ戻れる。
- API応答の `uid`, `nickname`, `bio`, `socialLinks` のみ表示し、累計やメールを表示しない。
- プロフィールが空でも受信作品の閲覧・いいね・保存は妨げない。
- 参照不可と通信失敗を異なる表示にし、通信失敗は再試行できる。
- 作品画像のURL・Storageパス・相手の受信箱情報をプロフィール画面へ渡さない。
- 描き手が非公開を選んだ場合、受信箱のAPI応答・UI・プロフィールAPIの全経路でユーザーネーム、自己紹介、SNSリンクを見られない。
- 非公開設定は受信者本人に紐づく作品IDだけで検証し、作者UIDやrecipient UIDのクライアント指定で迂回できない。
- 送信再試行・二重送信でも確定した公開選択が変わらず、公開設定がない過去作品は非公開として扱う。
- SNSリンクはURLのホストを表示して外部遷移することを分かる形にする。
- 過去の作品詳細に保持された送信時点の作者名と、プロフィールAPIが返す最新のユーザーネームを画面上で混同させない。
- スマホ320px・タブレット768px・PC1280pxで横はみ出しがない。
- 作品期限到達・手動削除後に作品詳細の操作を続行できない現行ルールを維持する。

## 9. 開発時に必要な確認

- 公開チェック欄の文言と既定値（本案はオフ）をデザイン確定時に確認する。
- 作品閲覧期限後にプロフィールへの導線を残さないことを確認する。
- `other` SNSリンクの警告文と、外部ブラウザー起動の可否を確認する。
- 将来、送信ごとの選択とは別にプロフィール全体の公開・非公開設定を導入する場合は、タイムライン等の名前表示・プロフィール遷移も合わせて設計する。
